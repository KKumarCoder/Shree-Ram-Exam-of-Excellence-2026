## Included

- React + Vite student portal with ten optimized, supplied Olympiad visuals and the original school crest.
- Real MongoDB-backed application with school-specific `APP-...` reference and post-verification `SHREE26-000001` registration number.
- Email OTP through Nodemailer SMTP, shared MongoDB rate limits/cooldowns, attempt limits, expiring one-time authorization and explicit local development delivery.
- Two payment workflows: official UPI QR + receipt + bank-reviewed manual approval, or Razorpay hosted checkout + signature + provider captured-status + HMAC webhook.
- On confirmed payment: registration number, automatic email with admit card and receipt attachments (durable retries), private PDF admit card with genuine server-generated QR, optional uploaded student photo.
- Student status search with a new OTP, admin dashboard, CSV export, payment approval/rejection, QR check-in and event settings.
- Local setup and VPS deployment instructions in this README.

**No test students, dummy payment receipt, hardcoded OTP, provider keys or live merchant credentials are included.** The illustrated QR codes in the promotional images are decorative. The actual UPI and admit QR are generated by the backend.

## Start locally (Mac/Windows/Linux with Node.js >=20)

1. Install Node.js, npm and connect MongoDB Atlas; create database credentials.
2. In `server`, copy `.env.example` to `.env`. Fill in `MONGODB_URI`, `FRONTEND_URL`, `JWT_SECRET` (32+ random chars) and `OTP_HASH_SECRET` (different random string; existing `OTP_PEPPER` is supported).
3. Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` (Gmail App Password) and `SMTP_FROM`. Set `OTP_DELIVERY_MODE=email`, `OTP_ENABLED=true`, `OTP_DEV_MODE=false`. SMS credentials are no longer used.
4. Set `ADMIN_EMAIL` and a strong `ADMIN_PASSWORD` (12+ characters) in `server/.env`.
5. From project root:

```bash
npm install
npm run install:all
npm run seed:admin
npm run dev
```

6. Open `http://localhost:5173`. Admin login: `http://localhost:5173/admin`.
7. Admin → Event settings → add _real_ school UPI ID and payee, confirm school policies, then enable registrations. Until then the form stays closed by default.
8. To use Razorpay, add its three secrets and switch payment mode in admin settings after a real integration test.

### Local testing

```bash

```

The JavaScript and JSX source can be inspected without a database. The integration tests use an isolated local MongoDB and mocked SMTP delivery; they never send real emails. Run `OTP_TEST_MONGODB_URI=mongodb://127.0.0.1:27039/shree_otp_test npm run test:integration --prefix server` with an isolated MongoDB instance running on that port; never use the application database.

## How to use

### Manual school UPI flow

Guardian completes student form → receives authorized OTP → reviews official generated UPI QR → pays ₹149 to the _configured_ school merchant → enters real UTR and uploads receipt → receives `APP-...` pending reference. Admin independently checks bank/UPI records, downloads private receipt, approves or rejects. Only upon approval does `SHREE26-...` get issued. Admit card and receipt are automatically emailed; the Status page also provides downloads after email OTP verification.

### Verified gateway flow

Select Razorpay in admin after configuring live keys/webhook. Guardian completes OTP → accepts terms → creates an actual order → pays via hosted provider checkout → backend checks checkout HMAC _and_ fetches payment to confirm status, exact order, INR and amount. A captured-payment webhook independently supports confirmation. Once confirmed, the PDF can be downloaded in the same session.

### Student photography

Required JPEG/PNG photos up to 5 MB are uploaded to authenticated Cloudinary storage and printed on server-generated PDFs. Payment receipts accept JPEG/PNG/PDF up to 3 MB. Configure `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` in the backend environment before starting the server. Never expose these through frontend variables.

## Production on Hostinger VPS

1. Point an `A` record for `olympiad.srpskanhra.com` to your VPS without changing existing `srpskanhra.com` records.
2. Clone or upload this project to `/var/www/shree-olympiad-mern` and run installation/build commands above (omit `npm run dev`).
3. Configure `.env` using production MongoDB, secrets, real OTP provider, public URL and **exact** `FRONTEND_URL=https://olympiad.srpskanhra.com`, `PUBLIC_BASE_URL=https://olympiad.srpskanhra.com`.
4. Install PM2 (`npm install -g pm2`); from root run `pm2 start ecosystem.config.cjs && pm2 save`; enable startup per PM2 instructions.
5. Copy the Nginx example below into your Nginx sites configuration; correct `root` and activate site. Run `sudo nginx -t && sudo systemctl reload nginx`.
6. Install an HTTPS certificate using Certbot (`sudo certbot --nginx -d olympiad.srpskanhra.com`).
7. Add `https://olympiad.srpskanhra.com/api/webhooks/razorpay` as the provider webhook URL when using Razorpay.
8. Test a registration under controlled conditions and ensure no dummy OTP mode, credentials or placeholder legal terms remain.

### Nginx configuration example

```nginx
# Save as /etc/nginx/sites-available/olympiad.srpskanhra.com
# Replace the project path, set DNS A record, and configure HTTPS via certbot.
server {
    listen 80;
    server_name olympiad.srpskanhra.com;
    root /var/www/shree-olympiad-mern/client/dist;
    index index.html;
    # 5 MB student photo plus multipart form overhead.
    client_max_body_size 6M;

    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        add_header Cache-Control "no-store" always;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

The example config only opens the new _subdomain_. Do not overwrite the existing school website's Nginx configuration.

## Environment and operational notes

- Configure the three backend Cloudinary credentials and run `npm run check:cloudinary --prefix server`. Uploads are held in memory and saved only to protected Cloudinary assets.
- For other deployments with existing local uploads, stop the backend, run `npm run migrate:cloudinary --prefix server` for an inventory, then add `-- --apply` to migrate and verify files before restarting. Migration requires the original files; missing or invalid sources need recovery or replacement. Never publicly serve local backups.
- To replace an image, use its existing filename under `client/public/images/`; the 10 images are WEBP to improve loading speed.
- OTP uses SMTP email with challenge-bound HMAC digests. Payment confirmation emails include both PDFs and retry automatically after temporary failures. SMTP acceptance does not establish inbox delivery.
- The default scholarships and promotional awards require school approval. Avoid asserting eligibility or issuing refunds based solely on graphics.
- Before launch, verify production credentials, HTTPS, backups, school policies, payment verification, email delivery, private receipt downloads, and admit-card printing.

## Known scope boundaries

This starter does not include a real provider account, legal approval, automated refunds, bulk admit ZIP, SMS delivery callbacks, integrated QR scanner camera UI or an operational production deployment. The check-in endpoint accepts a verified QR token entered by staff. Browser-based PDF print styling is separate from the programmatic server PDF. Add these if required before broad public launch.
